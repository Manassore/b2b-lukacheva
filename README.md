# B2B Приёмка · Лукачёва v1.3

## Порядок выпуска

1. В основном справочнике проверьте `Клиенты!W1` («Краткое название») и лист `Объекты`. В журнале `Поступления` проверьте `Y1:Z1` (`object_id`, `object_name`). Эти изменения совместимы с работающим сервером 1.2.1.
2. Откройте существующий проект «B2B Лукачёва API». Замените содержимое `Code.gs` кодом из [server/Code.gs](server/Code.gs), сохранив текущий блок `CONFIG` целиком. Публичный исходник содержит заполнители для трёх ID таблиц.
3. Сохраните код и запустите `diagnoseDirectory` из редактора. Функция читает схему и справочник, выводит `apiVersion: 4`, число клиентов, активных объектов и клиентов с неуточнённым расчётом. Для начального набора ожидаются 28 клиентов и 2 объекта.
4. В **Развернуть → Управление развертываниями** выберите действующее веб-приложение, нажмите карандаш и выберите **Новая версия**. Сохраните текущие параметры доступа, исполнителя и адрес `/exec`. Проверьте этот адрес с действующим токеном в настроенном приложении: **Настройки → Проверить подключение** должно показать версию API 4.
5. Объедините ветку с `main`. Дождитесь публикации GitHub Pages, откройте приложение с интернетом и проверьте версию в шапке. На телефоне проверьте выбор обоих адресов Орешка и подтверждение следующей реальной приёмки в журнале.

При откате интерфейса локальная очередь и настройки остаются в существующем хранилище. Оставьте сервер 1.3, пока в очередях могут быть операции с объектами: старый интерфейс отправит их в неизменном формате, а старый сервер не сохранит связанный объект. Токены и `SYNC_MODE=DRY_RUN` сохраняют свои значения.

## Справочник и сводка

Используйте одну строку клиента. В листе «Объекты» добавляйте адреса с отдельными постоянными ID и тем же кодом клиента. Для отключения адреса снимите флажок «Активен». Сохраните строку и ID объекта, чтобы уже сохранённые на телефоне операции могли подтвердиться после подключения. Краткое название клиента можно менять без смены ID.

Сводка находится под последними поступлениями. Она использует учётную дату в Самаре и включает принятые изделия и подтверждённый фактический вес. Старые записи с пустым объектом входят в итог клиента в строке «Без указания объекта». Сумма по объектам вместе с этой строкой даёт итог клиента.

## Проверки

```sh
node --check app.js
node --check sw.js
node --check < server/Code.gs
node --test tests/backend.test.cjs
python3 tests/mobile.py
```

Серверные сценарии выполняются с моделью Google Sheets. Мобильный тест использует Chromium (`CHROMIUM` при нестандартном пути), Python Playwright, локальную копию сайта и тестовые ответы API. Тестовые поступления остаются в локальном окружении.
